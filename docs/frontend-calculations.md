# Инструкция для фронтендера: данные и расчеты калькулятора

Документ описывает контракт данных спреда и расчеты, которые должен выполнять frontend после подключения реального источника данных. Названия переменных ниже приведены в том виде, в котором они ожидаются от данных спреда.

## 1. Какие данные получить

Для начального состояния калькулятора нужен актуальный снимок спреда:

```ts
interface SpreadSnapshot {
  days: number
  spread: number
  fut_margin: number
  perp_margin: number
}
```

| Переменная | Что означает | Как использовать |
| --- | --- | --- |
| `days` | Календарных дней до экспирации | Начальное и максимальное значение поля «Дней в сделке» |
| `spread` | Текущее значение спреда | Начальное значение «Спред входа» |
| `fut_margin` | ГО одного срочного фьючерса | Один из вариантов ГО пары |
| `perp_margin` | ГО одного вечного фьючерса | Один из вариантов ГО пары |

Для ставок фандинга и расчета регрессии нужно запросить дневную историю этого же спреда минимум за последний календарный месяц:

```ts
interface SpreadDailyPoint {
  date: string       // YYYY-MM-DD или ISO datetime
  funding: number
  spread: number
  days?: number      // дней до экспирации на дату точки, если API это возвращает
}
```

Историю необходимо отсортировать по `date` по возрастанию. Записи с отсутствующим или нечисловым значением конкретного показателя не нужно превращать в ноль — их следует исключить из расчета этого показателя.

## 2. Дни сделки и рабочие дни

### Календарные дни

Количество дней до экспирации брать напрямую из переменной `days` актуального снимка спреда:

```ts
const baseDaysToExpiration = Math.max(0, Math.trunc(snapshot.days))
const initialDaysInTrade = baseDaysToExpiration
```

Пользователь может уменьшить срок сделки вручную. Допустимый диапазон:

```ts
0 <= daysInTrade <= baseDaysToExpiration
```

Действие «До экспирации» возвращает `daysInTrade` к значению `snapshot.days`.

### Рабочие дни

Рабочие дни нельзя брать из `days` или вычислять коэффициентом. Их нужно пересчитывать от текущей календарной даты на выбранный пользователем горизонт `daysInTrade`.

Для прототипа рабочими считаются понедельник–пятница. Интервал — следующие `daysInTrade` календарных дней после текущей даты; при `daysInTrade = 0` результат равен нулю.

```ts
function countWorkingDays(today: Date, daysInTrade: number): number {
  let result = 0

  for (let offset = 1; offset <= daysInTrade; offset += 1) {
    const date = addCalendarDays(today, offset)
    const weekday = date.getDay()

    if (weekday !== 0 && weekday !== 6) result += 1
  }

  return result
}
```

Если появится официальный календарь торгов MOEX, он должен заменить правило понедельник–пятница и учитывать праздники/неторговые дни. Важно нормализовать даты до календарной даты в одной выбранной timezone и не считать разницу через произвольные 24-часовые интервалы около переходов времени.

## 3. Ставки фандинга

Источник — переменная `funding` из дневной истории спреда за последний месяц. Значение не нужно преобразовывать в проценты.

После очистки и сортировки истории рассчитать три пресета:

```ts
averageMonth = arithmeticMean(allMonthPoints.map(point => point.funding))
average10Days = arithmeticMean(last10Points.map(point => point.funding))
lastDay = lastPoint.funding
```

- «Средняя за месяц» — среднее арифметическое всех доступных дневных `funding` за месяц.
- «Средняя за 10 дней» — среднее последних 10 доступных дневных значений. Если точек меньше 10, использовать все доступные и явно считать пресет неполным.
- «Последний день» — `funding` самой новой дневной точки.
- Начальным значением поля можно использовать `averageMonth`.

При пустой истории поле не должно незаметно получать `0`: показать состояние отсутствия данных и оставить возможность ручного ввода.

Итоговый фандинг сделки:

```ts
const fundingBase = fundingRate * 1_000 * pairs * workingDays

fundingResult = direction === 'Short'
  ? -fundingBase
  : direction === 'Long'
    ? fundingBase
    : 0
```

Знак связан с фактической позицией по вечному фьючерсу:

- `Short` спреда означает `Long` вечного фьючерса — при положительной ставке фандинг является расходом.
- `Long` спреда означает `Short` вечного фьючерса — при положительной ставке фандинг является доходом.

## 4. ГО и количество пар

По правилам MOEX ГО одной пары равно большему ГО из двух инструментов. Значения не складываются:

```ts
const marginPerPair = Math.max(snapshot.fut_margin, snapshot.perp_margin)
const defaultPositionMargin = pairs * marginPerPair
```

Для текущего снимка большее значение равно `13 054 ₽`, поэтому при одной паре расчетное ГО по позиции равно `13 054 ₽`.

Обе переменные должны быть конечными числами `>= 0`. Если одна из них отсутствует, нельзя рассчитывать максимум по единственному значению: расчет позиции следует пометить недоступным до получения обеих величин.

В интерфейсе `positionMargin` — редактируемое поле «ГО по позиции». До ручного изменения оно автоматически равно `defaultPositionMargin` и пересчитывается при изменении количества пар. После ручного изменения значение сохраняется. Действие «По правилам MOEX» повторно вычисляет значение по формуле выше и возвращает автоматический режим.

Количество пар — целое число `>= 1`. При изменении количества пар необходимо реактивно пересчитать ГО, доход от спреда, фандинг, комиссии, необходимый займ, ROI и годовую доходность.

## 5. Спред входа и направление

Начальный спред входа — текущее значение переменной `spread`:

```ts
spreadEntry = snapshot.spread
```

Направление определяется сравнением спредов входа и выхода:

```ts
if (spreadExit < spreadEntry) direction = 'Short'
if (spreadExit > spreadEntry) direction = 'Long'
if (spreadExit === spreadEntry) direction = 'Neutral'
```

## 6. Спред выхода

`spreadExit` хранится и участвует в расчетах с одним знаком после запятой.

При любом изменении `daysInTrade` спред выхода необходимо пересчитать. Пользователь может затем изменить его вручную; ручное значение сохраняется до следующего изменения срока сделки.

### Предпочтительный вариант: центральная линия линейной регрессии

Для регрессии использовать `spread` из дневной истории. Удобная независимая переменная — количество дней до экспирации на дату наблюдения:

```ts
const x = point.days ?? snapshot.days + calendarDaysBetween(point.date, today)
const y = point.spread
```

По валидным точкам рассчитывается обычная линейная регрессия `y = a + b × x`:

```ts
const xMean = mean(points.map(point => point.x))
const yMean = mean(points.map(point => point.y))

const b = sum(points.map(p => (p.x - xMean) * (p.y - yMean)))
  / sum(points.map(p => (p.x - xMean) ** 2))

const a = yMean - b * xMean
```

Чтобы траектория начиналась точно от актуального `snapshot.spread`, рекомендуется взять наклон центральной линии и привязать ее к текущей точке:

```ts
const remainingDaysAtExit = Math.max(snapshot.days - daysInTrade, 0)
const rawSpreadExit = snapshot.spread
  + b * (remainingDaysAtExit - snapshot.days)

const spreadExit = roundToOneDecimal(rawSpreadExit)
```

Это именно центральная линия, а не верхняя/нижняя граница доверительного интервала. Для расчета желательно иметь хотя бы 5–10 валидных дневных точек и ненулевую дисперсию `x`. Регрессию лучше рассчитывать на backend и возвращать коэффициенты `a`/`b`, если объем истории, правила фильтрации выбросов или состав контракта усложнятся.

Регрессия не гарантирует ноль к экспирации. Если обязательна сходимость к нулю, это должно быть отдельным продуктовым ограничением, а не скрытым clamp результата регрессии.

### Fallback: линейная сходимость к нулю

Если истории недостаточно или знаменатель регрессии равен нулю:

```ts
const boundedDays = clamp(daysInTrade, 0, snapshot.days)
const rawSpreadExit = snapshot.days > 0
  ? snapshot.spread * (1 - boundedDays / snapshot.days)
  : 0

const spreadExit = roundToOneDecimal(rawSpreadExit)
```

Frontend должен знать, какой метод использован, чтобы при необходимости показать пользователю «Регрессия» или «Линейная оценка».

## 7. Остальные формулы

```ts
totalMargin = positionMargin

spreadIncome = Math.abs(spreadEntry - spreadExit) * pairs

borrowedCapital = useLoan
  ? Math.max(totalMargin - ownCapital, 0)
  : 0

loanCostPerDay = borrowedCapital * loanRate / 100 / 365
loanCost = useLoan ? loanCostPerDay * daysInTrade : 0

commission = pairs * commissionPerContract * 4

dealResult = spreadIncome + fundingResult - loanCost - commission
```

ROI:

```ts
roiBase = borrowedCapital > 0
  ? Math.min(totalMargin, ownCapital)
  : totalMargin

roi = roiBase > 0 ? dealResult / roiBase : 0
annualizedReturn = daysInTrade > 0 ? roi / daysInTrade * 365 : 0
```

Для годовой доходности используются календарные, а не рабочие дни.

## 8. Рекомендуемая последовательность загрузки

1. Получить актуальный `SpreadSnapshot`.
2. Установить `daysInTrade = days`, `spreadEntry = spread` и рассчитать `positionMargin = pairs × max(fut_margin, perp_margin)`.
3. Параллельно запросить дневную историю спреда за месяц.
4. Из `funding` истории построить три пресета фандинга.
5. Из `spread` истории подготовить коэффициент регрессии.
6. Рассчитать `workingDays`, `spreadExit` и все результаты.
7. При изменении срока пересчитать рабочие дни и `spreadExit`; при изменении остальных полей реактивно пересчитать результаты.

На время загрузки истории текущий снимок можно показать сразу, но значения, зависящие от истории, должны иметь явное состояние загрузки. Ошибка истории не должна блокировать ручной ввод ставки фандинга и спреда выхода.

## 9. Минимальные проверки интеграции

- `days` корректно задает срок по умолчанию и верхнюю границу.
- Рабочие дни пересчитываются при каждом изменении срока.
- Пресеты используют именно `funding` дневной истории выбранного спреда.
- `spreadEntry` совпадает с актуальным `spread` снимка.
- `spreadExit` после любого автопересчета имеет один знак после запятой.
- Ручной `spreadExit` не меняется от несвязанных полей, но пересчитывается после изменения срока.
- расчетное `marginPerPair === max(fut_margin, perp_margin)`.
- действие «По правилам MOEX» устанавливает `positionMargin === pairs × marginPerPair`.
- ручное ГО сохраняется при изменении количества пар до явного сброса по правилам MOEX.
- Фандинг для Short отрицательный, для Long положительный и масштабируется по количеству пар.
- При пустой/частичной истории и отсутствующем ГО интерфейс показывает явную ошибку данных, а не подставляет нули.
