Нужно создать небольшой production-ready SPA-прототип калькулятора сделки для публикации на GitHub Pages.

Технологии:
- Vue 3
- Vite
- TypeScript
- Composition API / <script setup>
- без backend
- без Vue Router, если он реально не нужен
- без тяжелого UI-framework
- иконки можно взять из lucide-vue-next
- стили — обычный CSS/SCSS, аккуратно организованный

Приложение должно запускаться:

npm install
npm run dev

и собираться:

npm run build

После push в main оно должно автоматически деплоиться на GitHub Pages через GitHub Actions.

ВАЖНО:
- Сделай именно рабочий интерактивный прототип, а не статическую верстку.
- Все вычисляемые показатели должны обновляться реактивно сразу после изменения любого входного параметра.
- Основной источник истины по формулам — описание ниже, а не цифры на приложенном UI-макете.
- Визуально ориентируйся на приложенный макет калькулятора: современный лаконичный dark fintech UI.
- Не надо пытаться пиксель-в-пиксель повторить картинку. Нужно сделать хороший профессиональный интерфейс с тем же составом данных и примерно той же компоновкой.

# 1. Общий интерфейс

Название:

"Калькулятор сделки для спреда срочный / вечный фьючерс MOEX"

Подзаголовок:

"Оценка доходности сделки с учетом фандинга, займа и комиссий"

Интерфейс разделить на два основных блока:

1. Параметры сделки
2. Результаты

Desktop-first, но интерфейс должен нормально перестраиваться на узком экране.

Стиль:
- темный фон;
- темно-синие / графитовые панели;
- аккуратные границы;
- radius примерно 10–14 px;
- хороший spacing;
- минимум декоративного шума;
- input-поля достаточно крупные;
- положительные результаты — зеленые;
- отрицательные — красные;
- readonly/calculated values визуально отличать от editable input;
- быстрые варианты выбора оформлять компактными chips/buttons.

Не делать огромные карточки и лишнюю "дашбордность". Это утилитарный калькулятор, информация должна помещаться достаточно компактно.

# 3. Количество дней

Поле:

"Дней в сделке"

По умолчанию рассчитывается автоматически:

expirationDate - текущая календарная дата

Значение целое.

Пользователь может вручную изменить количество дней.

Рядом показать calculated value:

"Рабочих дней: N"

Рабочие дни для прототипа считаем как понедельник–пятница без учета российских государственных праздников.

Если пользователь вручную указал, например, 20 календарных дней, рабочие дни считаются от сегодняшней даты на соответствующий горизонт.

Рядом с полем желательно дать маленькое действие:

"До экспирации"

которое сбрасывает пользовательское значение обратно на автоматически рассчитанное.

Не допускать отрицательное количество дней.

# 4. Ставка фандинга

Поле:

"Ставка фандинга, ₽/день"

Editable number.

По умолчанию:

0.012

Это именно РУБЛИ, не проценты.

В итоговом расчете ставка применяется с множителем 1000, количеством пар контрактов и количеством рабочих дней.

Справа расположить три компактных quick-fill значения:

"Средняя за месяц 0.012"
"Средняя за 10 дней 0.0154"
"Последний день 0.03"

При клике соответствующее значение попадает в input.

Пользователь также может ввести ставку вручную.

# 5. Количество пар контрактов

Поле:

"Пар контрактов"

Только целое положительное число.

Default:

1

Рядом readonly calculated value:

"Общее ГО: 24 700 ₽"

Формула:

totalMargin = pairs * marginPerPair

marginPerPair = 24700 ₽

# 6. Собственный капитал

Editable field:

"Собственный капитал, ₽"

Default:

500000

Значение >= 0.

# 7. Заемный капитал

Toggle:

"Использовать заемный капитал"

По умолчанию OFF.

Когда toggle выключен:
- поля займа полностью скрыты;
- показатель "Займ" в результатах также скрыт.

Когда toggle включен, появляется компактный блок займа.

В нем:

### Заемный капитал, ₽

Readonly.

borrowedCapital = max(totalMargin - ownCapital, 0)

### Ставка займа, % годовых

Editable.

Default:

21

### Стоимость займа в день

Readonly.

loanCostPerDay = borrowedCapital * loanRate / 100 / 365

### Плечо

Readonly небольшим badge/chip.

Если ownCapital > 0:

totalCapital = ownCapital + borrowedCapital

leverage = totalCapital / ownCapital

Показывать, например:

"Плечо: 2.47×"

Если заемный капитал = 0, плечо будет 1.00×.

Корректно обработать ownCapital = 0: не показывать Infinity/NaN.

# 8. Спред входа

Editable:

"Спред входа, ₽"

Default:

645

Может быть как положительным, так и отрицательным.

# 9. Спред выхода

Editable:

"Спред выхода, ₽"

Значение хранить и показывать с одним знаком после запятой. Результат автоматического пересчета также округлять до одного знака до использования в остальных формулах.

Изначально при полном сроке до экспирации:

0

Но здесь есть важная автоматическая логика.

Базовое предположение:

текущий spreadEntry = 645 должен линейно прийти к 0 через первоначальные 37 календарных дней до экспирации.

То есть при уменьшении количества дней в сделке автоматически рассчитываем spreadExit по линейной траектории.

Зафиксировать baseline:

baseDaysToExpiration = автоматически рассчитанное число дней до expirationDate
baseEntrySpread = исходное значение spreadEntry

Автоматический расчет:

spreadExit =
    spreadEntry * (1 - daysInTrade / baseDaysToExpiration)

При daysInTrade = baseDaysToExpiration:
spreadExit = 0

Например, примерно посередине срока spreadExit должен быть примерно половиной spreadEntry.

Ограничить daysInTrade сверху baseDaysToExpiration для этого сценария либо корректно обработать превышение.

Но пользователь МОЖЕТ вручную изменить spreadExit.

После ручного изменения spreadExit автоматически больше не пересчитывать при каждом изменении unrelated-поля.

Если после этого пользователь изменил "Дней в сделке", spreadExit снова можно пересчитать автоматически — это ожидаемое поведение.

Под полем показать небольшую подсказку:

"Автопересчет по линейной сходимости к 0 к экспирации"

# 10. Направление сделки

Показывать readonly badge:

"Направление сделки: Short"

или:

"Направление сделки: Long"

Правило:

if spreadExit < spreadEntry:
    direction = Short

if spreadExit > spreadEntry:
    direction = Long

if spreadExit === spreadEntry:
    direction = Neutral

Short оформить красноватым/оранжевым акцентом,
Long — зеленым/голубым,
Neutral — серым.

Важно: направление обозначает направление сделки по спреду. При Short спреда вечный фьючерс находится в Long, поэтому при положительной ставке фандинг является расходом. При Long спреда вечный фьючерс находится в Short, поэтому фандинг является доходом.

# 11. Расчеты результатов

Все расчеты должны находиться в одном месте:
например, composable:

src/composables/useDealCalculator.ts

Не размазывать бизнес-логику по template.

## Доход от сведения спреда

spreadIncome =
    abs(spreadEntry - spreadExit) * pairs

## Фандинг

Если Short:

fundingResult =
    -fundingRate * 1000 * pairs * workingDays

Если Long:

fundingResult =
    fundingRate * 1000 * pairs * workingDays

Если Neutral:

0

ВАЖНО:
используй именно эту формулу. Множитель 1000 и количество пар контрактов обязательны.
Знак определяется позицией по вечному фьючерсу: Short спреда означает Long вечного фьючерса и отрицательный фандинг; Long спреда означает Short вечного фьючерса и положительный фандинг.

## Займ

Если заемный капитал включен:

loanCost =
    loanCostPerDay * daysInTrade

Если заемный капитал выключен:

loanCost = 0

## Комиссии

commission =
    pairs * 0.45 * 4

То есть при одной паре:

1 * 0.45 * 4 = 1.8 ₽

## Результат сделки

dealResult =
    spreadIncome
    + fundingResult
    - loanCost
    - commission

# 12. ROI

Если borrowedCapital > 0:

roiBase = min(totalMargin, ownCapital)

И:

ROI = dealResult / roiBase

Если займа фактически нет:

ROI = dealResult / totalMargin

Обработать деление на 0.

В UI показывать ROI в процентах:

ROI * 100

# 13. Годовых

annualizedReturn =
    ROI / daysInTrade * 365

В UI показывать в процентах.

Используем именно КАЛЕНДАРНЫЕ дни сделки, а не рабочие.

Обработать daysInTrade = 0.

# 14. Блок результатов

Сначала компактный ряд показателей:

- Доход от сведения спреда
- Фандинг
- Займ — показывается только если включен заемный капитал
- Комиссии

Для каждого:
- название;
- крупное значение;
- ₽;
- цвет в зависимости от знака.

Затем более заметная summary-панель:

- Результат сделки
- ROI сделки
- Годовых

Результат сделки — визуально самый важный показатель.

Не надо использовать зеленый цвет для любого числа просто потому, что это metric.
Цвет зависит от знака:
- > 0 green
- < 0 red
- = 0 neutral

# 15. Форматирование

Деньги:
- locale ru-RU
- пробел как разделитель тысяч
- ₽
- разумное количество decimal places

Например:

24 700 ₽
500 000 ₽
643,52 ₽

Ставку фандинга не округлять до двух знаков — должны корректно отображаться значения типа:

0.012
0.0154

Проценты:
например:
21%
2,61%
25,7%

Избегать floating point мусора вроде:

643.52399999997

# 16. Проверочный сценарий

При:

daysInTrade = 37
workingDays = 27
fundingRate = 0.012
pairs = 1
totalMargin = 24700
ownCapital = 500000
borrowedCapital = disabled / 0
spreadEntry = 645
spreadExit = 0

должно получиться примерно:

spreadIncome = 645 ₽
funding = -324 ₽
commission = 1.8 ₽
loan = 0
dealResult = 319.2 ₽

ROI:

319.2 / 24700 ≈ 0.01292
=> около 1.29%

Годовых:

1.292% / 37 * 365
=> около 12.75%

Используй этот сценарий как sanity check.

Не используй положительный фандинг +324 ₽ и результат 967.2 ₽ из визуального mockup. Для направления Short корректный фандинг равен -324 ₽, потому что вечный фьючерс находится в Long.
